01 · Hackathon Context

The constraint

Hack-A-Damien gave every team 24 hours and a rule that shaped the whole project: the game could only accept one kind of input. Our team of five picked hand gestures, tracked live through a webcam, as that one input — which meant someone had to build a real-time computer vision pipeline from scratch, inside a 24-hour clock, before there was a game to plug it into.

02 · My Role

What I built vs. what my team built

This was a 5-person team project. I want to be exact about scope here rather than let a single project card blur it: I owned the hand-tracking pipeline end to end, solo. I did not build the game.

Mine — Solo
  • Webcam capture and frame handling (OpenCV)
  • Hand landmark detection (MediaPipe HandLandmarker)
  • Gesture detection/classification from landmarks
  • Streaming gesture events out over WebSockets, with Flask managing the data flow
My Teammates — Game Dev & Art
  • The Godot game itself — mechanics, levels, art direction
  • Receiving and acting on the gesture events my pipeline sent
  • Everything visual and playable about the finished game

I took the hand-tracking piece specifically because it was the most technically unfamiliar part of the stack — nobody on the team had built a real-time CV pipeline before, and someone had to own that risk so the rest of the team could commit their 24 hours to the game instead of hedging on whether input would work at all.

What the local evidence actually shows

I still have the script I used to get hand detection working: OpenCV opens the webcam, MediaPipe's HandLandmarker runs in IMAGE mode against each frame, configured for up to two hands, and prints the detected landmarks. That file and the MediaPipe model it loads are both dated April 25, 2026 — hours before the Godot project folder was created that same night, which lines up with Hack-A-Damien's timeframe.

The gesture-classification logic, the WebSocket message format, and the Godot-side receiving code aren't in any file I still have locally — the Godot project folder on this machine contains only the base project scaffold and imported art assets, no gameplay or networking scripts. I'm reporting those pieces from the resume and my own memory of building them, not from source I re-verified for this write-up.

05 · Iteration

What I can actually evidence

test.py is a real, specific engineering choice, not just a demo script: it runs HandLandmarker in RunningMode.IMAGE, detecting each frame independently rather than using MediaPipe's video-optimized streaming mode. That reads as an early, low-risk step — get detection working reliably on a single frame before building anything that depends on it running continuously in real time.

What I don't have is a documented record of the specific change between that step and the real-time pipeline that actually shipped — whether that meant switching running modes, adding smoothing across frames, or something else. I know it worked well enough to ship and place 4th, but I can't point to the exact diff without inventing one.

06 · Testing & Validation

How I checked it worked

test.py is itself how I validated the tracking foundation: run the webcam loop, print every detection result to the console, and watch the live frame in an OpenCV window at the same time — a direct, visual check that landmarks were actually being found before building anything on top of that signal.

08 · Lessons & Next Steps

What I learned, what I'd change

  • I learned that owning the unfamiliar, high-risk piece of a team project — rather than the safest task — is how you actually find out what you can build under pressure.
  • I learned that a small, disposable test script (get one thing verifiably working before connecting it to anything else) is worth the ten minutes it costs, even on a 24-hour clock.
  • With more time, I'd keep dated notes or commits through the build instead of just the working code — so a write-up like this could show the real iteration story instead of having to mark it undocumented.
  • With more time, I'd also go back and re-verify the gesture-classification and WebSocket code against whatever's recoverable, rather than reporting it from memory.
